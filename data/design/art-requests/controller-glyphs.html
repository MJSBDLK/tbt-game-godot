One pad, four skins

The engine side is already done. Godot normalizes every controller into one virtual Xbox-layout pad, so there is one set of bindings — the only per-controller difference is which picture we show for a button. The game already detects the connected pad's family and picks a skin (HintBarCommands.JoySkin): Steam Deck (primary target), Xbox (the fallback, and what Steam Input reports), PlayStation, Nintendo. Art is the only missing piece.

The cheat that makes this small: sprites are named by what they depict, not by which button they sit on. Steam Deck and Xbox share the same face letters. A Switch pad prints the same four letters in swapped positions — the code does the swapping, the letter sprites are reused as-is. Only PlayStation's shape glyphs are genuinely new art. Skins two through four are mostly free.

Sprite spec

Canvas

10×10 px — the established move-type icon size. The bar row is 14 px tall (8 px text + padding), so 10×10 sits flush beside the verbs.

Two-character labels (LB, ZL…) may widen the chip — the style guide already locks the "chip expands to fit" precedent. Keep height at 10.

Color

Default: 1-bit — white glyph on transparency. The engine draws the plate behind it (Gray-ramp chip, 1 px border, rounded 2) and can tint per state.

Canonical PlayStation shape colors are a possible later variant — your call, veto the 1-bit default on sight if it reads wrong.

States

One state per glyph. Pressed / dimmed / disabled are engine tints, not extra art. No animation frames.

Delivery

One .aseprite with a tag per glyph (the tag exporter handles the rest), or loose PNGs into art/sprites/ui/controller_glyphs/.

Name by depiction: letter_a, shape_cross, label_lb, icon_view, stick_r3, dpad. The code maps skin + button → sprite.
