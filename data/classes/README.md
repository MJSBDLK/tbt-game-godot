# Class data

The source of truth for classes and promotion trees. Edit it in the class tree
editor (`tools/art_dashboard/class_trees.html`, pointed at this folder) or by
hand; the game reads it through `ClassTrees`, and `tests/unit/test_class_trees.gd`
fails on anything malformed. The editor checks this README exists to confirm
the right folder was picked, so keep it. Rules and reasoning:
`data/design/class-and-promotion.md`.

Classes are a shared pool; each unit has its own tree drawing from it, so two
units that start as the same class can diverge at 21, or not. Typing is the
unit's, not the class's: each tree slot sets its own, so Ernesto's Colossus
can be Simple/Robo and the Ice Archer's mono Cold.

## `pool/<class>.json`: one class

```json
{
	"name": "Plague Doc",
	"tier": 3,
	"notes": ""
}
```

- The file name is the class's id: its name in lowercase, accents dropped,
  words joined by `_` (`El Capitán` → `el_capitan`).
- `tier`: 1 (base, levels 1-20), 2 (21-40) or 3 (41-60).
- No typing here: that's each tree's (below).

## `trees/<unit>.json`: one unit's tree

```json
{
	"base": "herbalist",
	"base_types": ["Monster"],
	"promotions": [
		{"class": "apothecary", "types": ["Monster", "Plant"], "art": "palette", "promotions": [
			{"class": "plague_doc", "types": ["Monster"], "art": "palette"},
			{"class": "distiller", "types": ["Monster", "Plant"], "art": "palette"}
		]},
		{"class": "sawbones", "types": ["Monster", "Simple"], "art": "palette", "promotions": [
			{"class": "chirurgeon", "types": ["Monster", "Simple"], "art": "palette"},
			{"class": "thaumaturge", "types": ["Monster", "Occult"], "art": "palette"}
		]}
	],
	"notes": ""
}
```

- The file name is the unit's character JSON name (`spaceman`, `healer_goblin`).
  A tree with no such unit yet (`thief`, `bugler`) is a design waiting for one.
- Always the full shape: a base, two tier-2 promotions, two tier-3 under each.
  `"class": ""` is a slot not designed yet.
- `types` on a slot, `base_types` for the base: the unit's typing as that
  class, zero to two elemental types spelled as in the character JSONs
  (`Simple`, `Heraldic`, ...). Empty means not designed yet.
- `draft` (optional, only beside `"class": ""`): a class in the making for an
  empty promotion slot, `{"name", "notes"}`, either blank, so brainstorming
  doesn't fill the pool with half-ideas. The editor shows it; the game reads
  the slot as empty. The editor's "Make it a class" turns it into a pool
  class, notes included. The base is always a class.
- Each slot's class has that slot's tier. The two tier-2 classes differ, and
  a tier-2 class never promotes into the same class twice. One tier-3 class
  may sit under both tier-2 classes: a middle ground either path reaches,
  making a 6-class tree. Only one.
- `art` is how that class's art gets made for this unit:
  - `palette`: generated by recoloring the unit's clothes layer (the default).
  - `palette_layer`: the same, plus a touch-up layer named after the class in
    the unit's .aseprite (Max's jetpack).
  - `redraw`: drawn from scratch (the Plant Cultist).
- `base` and `base_types` are the design. A unit's `currentClass` and types
  in its character JSON follow them once trees are wired into the game.
